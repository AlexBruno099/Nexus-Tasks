# Ajustes do frontend — 19/10/2026

A revisão identificou ajustes necessários no tratamento de falhas, na ordem das
gravações, no autosave e na navegação por teclado. Foram aplicados mantendo a
separação entre `server/` (backend) e `web/` (frontend).

## Organização

| Pasta                 | Responsabilidade                                    |
| --------------------- | --------------------------------------------------- |
| `server/`             | Rotas Fastify, acesso ao PostgreSQL e migrações     |
| `web/src/api/`        | Endpoints, cliente HTTP e fila de gravações         |
| `web/src/hooks/`      | Estado do quadro, notificações, autosave e diálogos |
| `web/src/components/` | Apresentação e interação com as telas               |
| `web/src/config/`     | Limites dos formulários conforme a API              |
| `web/tests/`          | Testes do cliente HTTP e das gravações em fila      |

`App.tsx` concentra a composição das telas, filtros e navegação. O carregamento
e as operações sobre os dados foram extraídos para `useBoard`.

## Comportamentos ajustados

- Leituras antigas são canceladas ou ignoradas após uma nova operação. As
  gravações são enviadas na ordem das ações, e uma falha não bloqueia a fila.
  Ao terminar, o quadro é reconciliado com a resposta atual da API.
- Falhas de conexão, timeout, respostas inválidas e erros HTTP têm mensagens
  legíveis. Uma escrita não é reenviada automaticamente depois de um timeout.
- O quadro tem botão para atualizar os dados, indicação de gravação e aviso
  com opção de recuperação quando a atualização falha.
- O arquivo exibe erro e permite tentar novamente, em vez de manter uma tela
  de carregamento indefinida. Restauração e exclusão evitam cliques repetidos.
  Exclusão permanente de uma tarefa arquivada exige confirmação.
- Criações rápidas de tarefas, etiquetas e branches evitam envios duplicados.
  Campos de edição respeitam os limites de tamanho aceitos pela API.
- O autosave preserva os rascunhos ao fechar o diálogo e não fica reenviando
  uma mesma edição recusada. Excluir uma tarefa cancela rascunhos pendentes;
  arquivar envia as edições antes do arquivamento.
- Diálogos mantêm Tab e Shift+Tab dentro deles, fecham com Escape e devolvem
  o foco ao acionador quando ele continua disponível. A altura é limitada ao
  espaço da janela, com rolagem interna.
- A interface desabilita exclusões de branches trancadas e de suas tarefas.
- A criação por uma página de branch verifica se há coluna disponível.
- `BOBINA_API_TARGET` permite executar a interface com o mock ou com a API
  temporária, mantendo as requisições em `/api` na mesma origem.

Os fluxos de escrita no navegador usaram a API Sandbox em `:3334` e um banco
temporário. A interface de desenvolvimento usou `:5174` com proxy para esse
Sandbox. O banco diário não foi usado para as operações de teste.

## Limite destas alterações

Não houve mudança no contrato nem na implementação do backend. As pendências
funcionais e de segurança registradas em `auditoria-2026-10-19.md` continuam
necessitando de correção no servidor. Em particular, desabilitar exclusões na
interface não protege os endpoints contra requisições diretas.

O mock e as coleções do Postman continuam disponíveis. As instruções de uso da
interface com esses ambientes estão no README do projeto.
